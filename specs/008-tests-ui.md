# 008 – Tests UI: the Tests screen looks and works like the Trainer

## Why
The Tests and Trainer screens were built separately and look different: Tests
uses dropdowns, the Trainer uses buttons and shows an example task. A user
moving between the two tabs should find the same design and the same controls.
Only the look of the Tests choice screen changes; the test rules stay exactly
as they are.

## What
The Tests choice screen (before Start) shows, from top to bottom:

1. The heading "Tests" and below it a short description in the Trainer's
   style (a caption): "Solve as many tasks as you can in 60 seconds. Only
   correct answers count."
2. **Operation:** a row of clickable buttons (pills), the same control the
   Trainer uses for its operations: Addition, Subtraction, Multiplication,
   Division, Random. Exactly one is selected; Addition at first.
3. **Level:** a segmented button row, the same control the Trainer uses for
   levels: Easy, Medium, Hard, Pro. Exactly one is selected; Easy at first.
4. **Example task:** a bordered box exactly like the Trainer's, captioned
   "Example task · Calculate", showing one task generated by `tasks.py` for
   the selected operation and level. For Random it shows one of the four
   operations. It changes when the selection changes and stays the same
   otherwise. It is display only: it is not counted, not saved, and is not
   the first task of the test.
5. The Start button and the Highscores table, as before.

The selection is remembered for the browser session, also after a test or
after visiting another tab, as before. Start begins a test with the selected
operation and level.

There is no Mode and no number of tasks on Tests: a test always lasts 60
seconds (MB R4).

### Shared components
The Trainer's choice buttons and example box move from `trainer_ui.py` into a
new shared module `ui_components.py`, used by both screens. The Trainer looks
and behaves exactly as before. `ui_components.py` contains only Streamlit
screen code: no rules and no SQL.

## Out of scope
Any change to `tasks.py`, `runs.py` or `db.py`, or to MB R1–R6: task ranges,
time limit, scoring, saving and highscores. The countdown, the running test
and the result screen. The Games tab, which keeps its level dropdown.
The look of the Trainer.

## Done when
- **Description:** the Tests screen shows the description under the heading.
- **Operation:** the Operation buttons offer exactly Addition, Subtraction,
  Multiplication, Division, Random, with Addition selected at first.
- **Level:** the Level buttons offer exactly Easy, Medium, Hard, Pro, with
  Easy selected at first.
- **No dropdowns, no mode:** the Tests screen has no dropdown and no number field.
- **Example task:** shown for every selection; its operation sign matches the
  selected operation (any of the four for Random), and its numbers follow MB R1
  for the selected level.
- **Not counted:** choosing operations and levels and viewing examples saves
  no run.
- **Start:** Division at Pro starts a Division Pro test.
- **Remembered:** after aborting a Division Pro test, Division and Pro are
  still selected.
- **No rule changes:** every existing test passes; in `tests/test_app.py` only
  the selectors for the two pickers change (dropdown → buttons), never an
  expected result. All Trainer tests pass unchanged.
